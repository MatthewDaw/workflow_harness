Feature — Topic-Focus Logging (capture what a session is working on, as it drifts)

As we log Claude messages, also log what the session is actually focused on — segmenting one conversation into topics and relabeling the current topic as focus drifts — and mine the manual correction turns into structured learnings. The learnings sharpen two agents over time: the implementing agent (so it one-shots vague prompts like "build a login page" to completion) and the doc-writing agent (so it asks better questions up front). End state: less correction needed.

Where it runs. The Claude API is stateless and stores nothing retrievable, so capture happens client-side; summarization runs wrapper-side on the dev's own Claude subscription over the local transcript JSONL the daemon already tails (wrapper/internal/capture/jsonl.go). No backend API key, no server-side LLM, no embeddings. Only small distilled records ship to HQ.

Builds on existing auto-titling. The daemon already runs a one-shot headless claude -p to title a session from its first exchange (internal/title/, spawned as a goroutine inside Runtime.captureLoop; see 04 — CLI wrapper). That gives the stable slug. Topic-focus logging is a new evolving layer on top — the slug never changes (no title thrash); the topic and a rolling description update as the work moves. The judge reuses the title runner's spawn pattern and lives in the same layer (captureLoop), not in daemon.go.

Decisions (confirmed 2026-06-06)

Four author calls surfaced by review, now decided.

  • D1 — Correction-turn timing. Detect the correction on UserPromptSubmit (the prompt that opens the turn), then run the judge on that turn's subsequent Stop after draining the tailer.
  • D2 — Secret/PII handling. Regex-scrub common secret patterns + hard length caps (impl_learning ≤ 500 chars, doc_question ≤ 300) before emit; no separate user opt-in for v1.
  • D3 — Cost ceilings. Gate thresholds Jaccard τ ≈ 0.3, debounce ≥ 3 turns or ≥ 1500 tokens; per-session cap 50 judge calls; daemon-wide concurrency cap (token bucket) of 2 concurrent judge spawns shared across tabs. (Tunable per the Open Questions.)
  • D4 — Learnings read authz. Owner-only for v1 (mirror ownedProject() in rest/projects.ts); revisit org-visibility later.

What we capture

  • Topic segments. A session is split into topic segments; the current topic is relabeled when focus drifts. Topic labels are session-local — never reconciled against anything outside the session.
  • Rich descriptions. Each topic carries a self-contained description (not a 3-word label) — feature/domain, what was built, what went wrong, the resolution — written so a later phase can search/cluster on it. Enforced at capture; expensive to retrofit.
  • Two learning streams (additive). Every correction turn yields an implementing-agent learning (impl_learning: a convention/fix), unconditionally. When a correction clearly contradicts the nearest doc, it additionally yields a doc-writing-agent learning (doc_question: a question to ask up front). The doc comparison never diverts a learning away from the impl stream. Works with zero docs. (Terminology: impl_learning and doc_question are the two learning-stream payloads; "doc learning" = a doc_question.)

Requirements

  • R1 Segment a session into topics and relabel the current topic on drift, without renaming the stable slug.
  • R2 On every correction turn, extract an impl_learning — where "every correction" means every turn the gate identifies as a correction (the correction cue must fire independently of file-churn, so same-file and no-edit corrections are not missed).
  • R3 On a high-confidence contradiction with the nearest doc, additionally extract a doc_question.
  • R4 Each topic carries a rich, self-contained, search-ready description.
  • R5 Persist topic, rolling description, and routed learnings into HQ; surface topics within the session UI.
  • R6 Everything works with no documentation present.
  • R7 Summarization runs wrapper-side on the dev's subscription (headless Haiku), gated and rate-capped so cost is bounded, off the turn's critical path.
  • R8 Expose stored learnings via a read endpoint — the hand-off stub for the deferred optimize loop.

Key design decisions

  • Judge in Runtime.captureLoop, off the critical path. The gate/judge needs the per-tab tailer state, transcript path, repoRoot, projectID, and the emit closure — all of which live in captureLoop (internal/daemon/runtime.go), where the proven title.Generate goroutine already runs. daemon.go ingestHook only has the SessionID; it forwards the Stop/UserPromptSubmit signal into captureLoop, which owns the gate. The model call is spawned on a goroutine (never blocks the turn).
  • Turn-cycle ordering (D1). Correction-smell is evaluated on UserPromptSubmit (the opening prompt); the judge runs on that turn's subsequent Stop, after the tailer has flushed the turn's tool_use rows (drain/Poll before computing the gate, to avoid an empty/stale file set).
  • Headless Haiku, isolated subprocess (D2/security). Reuse the internal/title/ claude -p spawn (own auth, claude-haiku-4-5), but: (a) set a dedicated CLAUDE_PLUS_JUDGE=1 env and add a skip-check for it in runHook (cmd/claude-plus/main.go) so the judge's own hooks never re-enter the daemon (prevents phantom sessions and a Stop→judge→Stop recursion); (b) build the child env explicitly (PATH, HOME, CLAUDE_CONFIG_DIR only) — do not inherit os.Environ() / CLAUDE_PLUS_DANGEROUS.
  • Injection-safe prompt. The transcript slice and doc content are untrusted; wrap them in explicit <transcript>/<doc> delimiters the system prompt marks as data-not-instructions, and validate the verdict against a strict schema before persisting.
  • Files-touched via JSONL re-parse (A4). The touched-file set comes from re-parsing the raw JSONL tool_use input.file_path of write-class tools (Edit/Write/MultiEdit/NotebookEdit), accumulated as per-session state in the tailer — not from tool.call argsSummary (single field, truncated). Bash-driven edits are not reliably captured; this is an accepted limitation of the lexical gate.
  • Cheap, embedding-free gate. Spend a judge call only on: a file-path Jaccard shift below τ (lexical TextTiling), a correction cue (fires independently of Jaccard), or a cadence/debounce floor — subject to the per-session and concurrency caps (D3).
  • Two new events, additive — with deploy ordering. session.topic folds into the projection; session.learning is an append record. Both added to the TS discriminated union (packages/shared/src/events.ts), the Go event package, and the golden fixture (Go json tags must mirror the Zod optional/required choices, with new golden rows). Because parseEnvelope hard-rejects unknown kinds, the backend (shared schema + Lambda) must deploy before any wrapper emits the new kinds — or ingest must tolerate-and-drop unknown kinds.
  • Idempotent learnings. Derive the session.learning seq from a stable turn id / transcript offset (not a free counter) so a judge retry or a mid-turn daemon restart can't write duplicates; dedupe on (sessionId, turnId) at ingest.
  • Observable failure. The "parse-once-retry-else-no-op" fallback is safe for the topic but silently drops a learning; emit a parse-failure marker (counter/log) so learning loss is observable, not invisible. Extract JSON via a fenced-block/first-balanced-object parse, not raw stdout.
  • Contradiction = explicit reversal, not staleness. Emit contradicts_doc only when the doc makes an explicit claim the correction reverses (not mere absence or a stale doc), and only when the nearest-doc heuristic has evidence the doc actually covers the touched file (else treat as no doc). Bias toward not-a-contradiction.
  • Carried context for self-contained descriptions. The judge receives the current rolling description + prior topic_label as carried state and updates rather than regenerates it — so a faithful description survives a topic spanning more turns than the bounded slice. Known limit: detail outside the slice relies on the carried description.
  • Learnings under the project partition. PK=PROJ#<projectId>, SK=LEARN#<sessionId>#<turnId>, read in one begins_with(SK,'LEARN#'); swept by the existing deleteProject() bulk-delete (no separate cleanup).
  • Title-thrash guard + debounce attribution. The slug never changes; topic/description evolve debounced. A new segment opens on a confirmed same_topic:false; during the debounce window, hold the turn's learnings/description delta pending and attribute to the correct segment once the switch resolves (avoids description bleed across the boundary).
  • Checkpoint store (C6). Per-session topic/cadence/debounce state is checkpointed to a small JSON file under the claude+ config dir keyed by tab session id (written after each fold, loaded on captureLoop start). Acceptable alt: ephemeral state with a documented cold-start.

How it works (turn cycle)

On UserPromptSubmit: mark whether this opening prompt smells like a correction (cheap cue, independent of file churn) and stash it on the session's gate state.

On Stop: keep today's status.change → idle immediately (do not wait on the judge). Drain the tailer so the turn's tool_use rows are flushed, then run the cheap gate (Jaccard shift on the touched-file set, the stashed correction cue, or the cadence floor), subject to the caps. If it fires, build inputs — bounded position-aware transcript slice (JSONL tail), files-touched set, nearest doc (only if it covers a touched file; else none), and the carried topic state (label + rolling description) — and spawn the isolated headless Haiku judge on a goroutine. Parse + schema-validate the verdict (retry once; on failure emit a parse-failure marker and keep the current topic). Fold: open a new segment on a confirmed same_topic:false (debounced, pending-attribution); always append impl_learning; append doc_question iff contradicts_doc; update the rolling description. Scrub + length-cap the output fields (D2), then emit session.topic and any session.learning via the existing emit path. Checkpoint state.

Verdict shape (directional): { same_topic, topic_label, description, is_correction, contradicts_doc, impl_learning?, doc_question? }.

Security & privacy

  • Subprocess isolation — explicit child env (no os.Environ(), no CLAUDE_PLUS_DANGEROUS); CLAUDE_PLUS_JUDGE=1 skip in runHook so the judge never spawns a phantom session or recurses.
  • Prompt injection — untrusted transcript/doc content delimited as data; verdict strictly schema-validated before persistence.
  • Secret/PII (D2) — regex-scrub + hard length caps on impl_learning/doc_question before they leave the machine; the "transcript stays local, only distilled records ship" boundary is enforced by this filter, not just asserted. Learnings cascade-delete with the project.
  • Cost/DoS (D3) — concrete gate thresholds + per-session cap + daemon-wide concurrency cap shared across tabs; judge cost tracked separately from interactive session cost.
  • Authz (D4) — the read endpoint inherits the same Cognito JWT authorizer and owner-check as the other /projects/:id/* routes.

Web UI

Two surfaces, kept deliberately simple for v1:

  • Sessions table (packages/web/src/screens/Sessions/SessionsTable.tsx) — the topic column replaces the frozen first-prompt column: topic label primary, the stable slug shown muted/secondary (so a user who navigated by slug isn't disoriented). Description is line-clamped to 2 lines with a hover tooltip. Before any topic exists, show a muted "Untitled" placeholder; topic updates arrive silently via the existing live WebSocket (staleness during the debounce window is acceptable, not surfaced).
  • Session detail — single-column: a topic timeline (chronological vertical list; each row = topic label + relative open-time + one-line clamped description; a new row appears only when a new segment opens, an in-place relabel updates the latest row), then two stacked labeled sections "Implementation learnings" and "Doc-writing learnings" (the doc section shows a zero-state, not hidden, since it's empty in the common case). Empty states: timeline "No topic segments yet"; impl "No corrections logged this session"; doc "No doc loaded — doc learnings appear when a correction contradicts a loaded doc".

Scope & deferred

  • In scope (v1): within-session topic segmentation + relabel on drift; correction mining into impl/doc learnings; rich descriptions; wrapper-side headless Haiku judge with a cheap gate + caps; the two events; projection/DTO fields; project-partition learnings table; the read endpoint; within-session UI. Docs-optional throughout.
  • Deferred — agent improvement loop. Feeding the stored learnings into hq-optimize-agent to actually edit the two agents (see 05 — AgentForge).
  • Deferred — cross-session semantic search. The agent-builder searching stored descriptions for similar topics. Server-side embeddings / Forge vector retrieval / OpenSearch were removed (see platform, "No server-side embeddings"), so this would be reintroduced client-side. v1 only guarantees the descriptions are rich enough to feed it.
  • Out of scope: verbatim transcript upload to HQ; any backend-side LLM call; cross-session topic grouping in the UI.

Open questions (deferred to implementation)

  • Exact claude -p flags / structured-output mechanism for reliably parseable JSON on Haiku.
  • Transcript-slice exact byte/token bounds (latest prompt + tail of last assistant turn + file list).
  • Nearest-doc "covers this file" heuristic specifics, incl. a doc-mtime staleness guard.
  • Tuning of the D3 gate-threshold numbers against real sessions (the defaults are starting points).

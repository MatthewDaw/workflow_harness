Defense

The hard questions

How do you know it's done?
The verifier owns done: empty mechanical gap list AND green gates, as a structured state change. The model's prose is ignored.
Won't 1000s of skills overflow context?
Nothing ever loads the full catalog — top-k vector search keeps context O(k) while the registry grows O(n). Same pattern as Claude Code's deferred tools.
What stops skill sprawl & duplication?
Dedup before every add (≥0.90 = route to existing skill), auto-split when oversized, and agent-description collisions are flagged as registry smells.
Isn't spec-writing overhead?
Tier-adaptive — a T0 fix's spec is one sentence + repro. Heavier ceremony is refused by rule.
What if it loops forever?
Gap-trend stall detection, same-error circuit breaker, no-diff detection, budget caps → escalate with evidence, never silent retry.
What if the spec is wrong?
First-class outcome: fix-the-code / fix-the-spec / fix-the-test. Additive changes auto-accept; breaking ones gate to a human.
Why will it improve over time?
Improvement is measured, not assumed: predicted metric per edit, canary + sequential testing, Goodhart counter-metrics. Losses revert.
Does parallelism even help?
Only where evidence supports it: read fan-out (+90% vs single agent), isolated writes (+14–27 pts vs shared workspace), capped ~4–6.
